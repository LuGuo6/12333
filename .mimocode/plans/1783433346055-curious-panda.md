# 用户态 Hook GL_RENDERER — 实现方案

## 目标

Hook `glGetString(GL_RENDERER)` 和 `glGetString(GL_VENDOR)`，让所有App（包括设备信息App）看到伪造的GPU信息。

## 方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **Zygisk 模块** | 注入每个App进程，hook `libGLESv2.so` 中的 `glGetString` | 最可靠，覆盖所有App | 需要 Magisk + Zygisk |
| LD_PRELOAD 伪造库 | 替换 `libEGL.so` / `libGLESv2.so` | 简单 | 可能导致图形异常 |
| Xposed 模块 | hook Java 层 | 简单 | `glGetString` 是 native 函数，Java 层hook不到 |

## 推荐方案：Zygisk 模块

### 原理

```
App 启动
  → Zygote fork 新进程
    → Zygisk 注入 module.so 到进程
      → module.so hook libGLESv2.so 的 glGetString PLT 条目
        → App 调用 glGetString(GL_RENDERER)
          → 被拦截，返回伪造值
```

### 模块结构

```
magisk_module/
├── module.prop              # 模块元数据
├── customize.sh             # 安装脚本
├── system.prop              # 系统属性（可选）
├── lib/
│   └── arm64-v8a/
│       └── module.so        # Zygisk 原生库
└── zygisk/
    └── arm64-v8a/
        └── module.so        # Zygisk 注入库
```

### 核心代码：hook glGetString

```c
// zygisk module.cpp
#include <EGL/egl.h>
#include <GLES2/gl2.h>
#include <string.h>

// 原始 glGetString 函数指针
typedef const GLubyte* (*glGetString_t)(GLenum);
static glGetString_t orig_glGetString = NULL;

// 伪造数据
#define FAKE_RENDERER "Immortalis-G925"
#define FAKE_VENDOR   "ARM"

const GLubyte* hook_glGetString(GLenum name) {
    const GLubyte* result = orig_glGetString(name);

    if (name == GL_RENDERER) {
        return (const GLubyte*)FAKE_RENDERER;
    }
    if (name == GL_VENDOR) {
        return (const GLubyte*)FAKE_VENDOR;
    }

    return result;
}

// Zygisk 入口
void onModuleLoaded() {
    // 获取原始 glGetString 地址
    void* handle = dlopen("libGLESv2.so", RTLD_NOW);
    orig_glGetString = (glGetString_t)dlsym(handle, "glGetString");

    // PLT hook（需要用 PLT hooking 库）
    // ...
}
```

### 关键技术点

1. **PLT Hooking**：修改 `libGLESv2.so` 的 PLT 表项，将 `glGetString` 的跳转地址改为我们的 hook 函数
2. **需要的库**：
   - `xhook` (Facebook 开源) — PLT hook 库
   - `bhook` (字节跳动开源) — 更现代的 PLT hook 库
   - 或者内联 hook（inline hook）— 直接修改函数入口

3. **Zygisk API**：Magisk 提供的 Zygisk 框架允许在每个 App 进程中注入 native 代码

### 需要修改的文件

| 文件 | 说明 |
|------|------|
| `module.prop` | 模块描述 |
| `zygisk/arm64-v8a/module.so` | 注入库，包含 glGetString hook |

### 验证方式

```bash
# 安装模块
adb push magisk_module.zip /sdcard/
# 在 Magisk App 中安装

# 重启设备后验证
# 打开设备信息App → GPU型号应显示 "Immortalis-G925"
# 打开任意OpenGL ES应用 → glGetString(GL_RENDERER) 返回 "Immortalis-G925"
```

## 与 KPM 模块的配合

| 层面 | 模块 | 覆盖范围 |
|------|------|----------|
| 内核态 sysfs | KPM `xuanjie_o1.kpm` | `cat gpu_model` → Immortalis-G925 |
| 用户态 EGL API | Zygisk 模块 | `glGetString(GL_RENDERER)` → Immortalis-G925 |

两者一起用，从内核到用户态完全伪装。
